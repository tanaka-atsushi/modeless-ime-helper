# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Windows 11 tray-resident Win32/C++17 app. Goal: with a Japanese composition still unconverted ("あいさつ"), the user holds the trigger key and types letters, which join the composition **as plain letters** ("あいさつaisatsu"); after releasing the trigger, one conversion gives "挨拶aisatsu". Trigger = left Shift by default; chosen in the tray menu from `kTriggerKeys` in `common.h`: left/right Shift, 無変換 (`VK_NONCONVERT`), 変換 (`VK_CONVERT`), カタカナひらがな (`0xF2`) — the user limited it to these (CapsLock, Alt, Ctrl, Windows and Menu were offered and removed again; an old saved value falls back to left Shift); saved as its vk in DWORD `TriggerShift` under `HKCU\Software\ime2nd` (name kept from when only Shift was possible). JIS keys also match by scan code (`TriggerKey::scan`: 変換 0x79, 無変換 0x7B, カタカナひらがな 0x70), because their vk can depend on the layout and modifiers (Shift+カタカナひらがな gives `VK_DBE_KATAKANA`).

How: while the IME is ON, the trigger key's press is **swallowed** by a low-level keyboard hook (the app never sees it, so keys typed meanwhile are plain unshifted keys), and `ImeSwitcher` injects `VK_IME_OFF` (Microsoft IME → half-width alphanumeric, composition kept). All other keys pass through untouched. On release it injects `VK_IME_ON` (back to hiragana). With the IME OFF nothing is intercepted (the trigger is an ordinary Shift / IME key). The other Shift is never touched, so trigger + other Shift + letter gives an uppercase letter. Must run **without admin rights** (`asInvoker`, no `uiAccess`, startup via `HKCU\...\Run` only); elevated apps are intentionally left alone (UIPI). See `README.md` for user-facing behavior.

This is a **prototype** (branch `bigcomi/stream-chars-to-app`). Earlier designs, for reference: buffer in a popup and inject on release with `SendInput(KEYEVENTF_UNICODE)` while the IME is closed (in git history: `PopupWindow`, `CaretLocator`, `TextInjector`, `ImeState::Suspend/Resume`); posting `WM_CHAR` per captured key (never committed). Both commit the pending composition, so they cannot reach the goal (see Gotchas).

## Commands

- Build: `build.bat` (or `build.bat debug` → `build-debug\`) → `build\ime2nd.exe`. It finds Visual Studio via `vswhere`, loads `vcvars64.bat`, then runs `cmake --preset release` / `cmake --build --preset release` (Ninja, `CMakePresets.json`). cmake/ninja come from PATH if present, otherwise from the copies bundled with VS (`Common7\IDE\CommonExtensions\Microsoft\CMake`). Installed here: VS 2026 Community (v18). Opening the folder in Visual Studio also works. No test suite or linter. Quit a running `build\ime2nd.exe` first, or linking fails (LNK1104).
- New `.cpp` files must be added to `add_executable` in `CMakeLists.txt`; new system libs to its `target_link_libraries`. `src/app.manifest` is listed as a source so CMake embeds it with `mt.exe`; CRT is static (`/MT` via `CMAKE_MSVC_RUNTIME_LIBRARY`).
- In `build.bat`, avoid parenthesized `if (...)` blocks: expanded `Program Files (x86)` paths contain `)` and break them.
- Smoke test: `build\ime2nd.exe --selftest`. It waits 3 s (focus a text field), reports the IME state and raw conversion mode, then runs the real hook (with `ImeSwitcher`) for 10 s and reports max callback time. Output goes to `build\selftest.txt` (GUI subsystem, no console).
- Injected input can't be used to test the hook (it ignores `LLKHF_INJECTED`), so the trigger path needs real keystrokes. The IME behavior it relies on can be checked without the hook by injecting `VK_IME_OFF`/`VK_IME_ON` and real keys into a dedicated Notepad tab titled `inj-test` (ask the user first; abort unless that tab is in front — see the memory note about not touching their desktop).

## Architecture

`main.cpp` owns a hidden message-only window (tray icon/menu, 30 s hook-reinstall timer) and a `SetWinEventHook` for foreground changes. `KeyboardHook` (LL hook, main thread) handles **only the trigger key**. `ImeSwitcher` is a worker thread with a message queue: the hook `PostThreadMessage`s Begin/End to it. `ImeState` answers "is the IME ON?" from a cache.

Constraints that shape the code:

- **The hook callback must stay microseconds-fast.** Windows silently removes LL hooks that exceed ~300 ms. So it does no allocation, no SendInput, no blocking sends (except `ImeState::Current()`'s ≤30 ms fallback query when the cache is stale); it flips state and posts. `main.cpp` re-installs the hook every 30 s (`Reinstall`) as a guard.
- **Trigger tracking from events** (`g_trigger`: Up / Swallowed / Passed). A swallowed key never reaches the system key-state table (measured with CapsLock: `GetAsyncKeyState` stays "up"), so `GetAsyncKeyState` can't be used for it. A fresh press is swallowed only if enabled, IME ON (`Unknown` counts as ON only with the tray option), and Ctrl/Alt/Win are **not** already down (eating the Shift of Ctrl+Shift+Z / Win+Shift+S would turn them into other shortcuts). Otherwise it is Passed: an ordinary key, and its repeats stay ordinary until release even if the IME turns ON meanwhile (the app already saw it go down). Repeats of a swallowed press are swallowed; its release is swallowed and ends the session. A missed release (elevated window in front) heals on the next press/release, on `ResetHeld()` (foreground change, trigger change) and on the reinstall tick (a Swallowed state can't be told from a stuck one, so the tick ends the session; a Passed one is checked with `GetAsyncKeyState`).
- **`ImeSwitcher`** (own thread, so injecting never happens inside the hook): Begin freezes the `ImeState` cache, injects `VK_IME_OFF` **first** (every ms before it a typed letter could still go in as kana — there is a small race right after the trigger press), then saves the foreground thread, the focus window's IME window and the conversion mode last read by `ImeState` (when the press was judged ON). End: if the foreground thread is unchanged, injects `VK_IME_ON` (ordered after the session's keys in the input stream, so no settle delay); if the saved mode was not hiragana (`conv & ~ROMAN != 9`), waits 150 ms and sets it with `IMC_SETCONVERSIONMODE`. If the foreground changed, only `IMC_SETCONVERSIONMODE` on the saved IME window, so the new window is not touched. Then unfreezes. Injected events carry `kInjectTag`; the hook ignores all `LLKHF_INJECTED` events.
- **IME state** (`ImeState`): cached, refreshed by a worker thread on foreground change (`SetWinEventHook`), at the end of a session, and 80 ms after an IME mode key passes the hook (`VK_KANJI`, `VK_IME_ON/OFF`, JIS 英数/半角全角 `0xF0–0xF6`, `VK_NONCONVERT`, `VK_KANA`, a non-trigger `VK_CAPITAL`). Uses `ImmGetDefaultIMEWnd` + `WM_IME_CONTROL/IMC_GETOPENSTATUS` (`ImmGetContext` doesn't work cross-process). **ON means open AND `IME_CMODE_NATIVE` set** (`IMC_GETCONVERSIONMODE`): the Windows 11 Microsoft IME stays "open" in its direct-input (A) mode and only clears the NATIVE bit (ON: open=1, conv=0x9; OFF: open=1, conv=0x0). Windows Terminal / XAML-island windows report open=0 with odd conv values, so they read as OFF. `Current()` falls back to a 30 ms synchronous query only if the cache is >400 ms old; that query uses `SMTO_BLOCK` so the hook can't re-enter. **Freeze:** during a session the IME really is in alphanumeric mode, so refreshes would cache "OFF" and a quick re-press would pass through; `Freeze(true)` (set by the switcher worker, ordered after the previous End) keeps the cache, and the hook calls `MarkOpen()` at release.
- **Caps Lock state:** if Caps Lock is ON, letters typed in a session come out uppercase (`GetKeyState(VK_CAPITAL) & 1` is the reliable read of it; the low bit of `GetAsyncKeyState` is always 1). CapsLock was a trigger choice earlier and was removed at the user's request.
- Manifest (`src/app.manifest`) is embedded at link time and sets PerMonitorV2 DPI.

## Gotchas

- **Mixing letters into a pending composition — measured in Notepad (`RichEditD2DPT`, 2026-10-11, scratch tool `imemix.cpp` injecting into an `inj-test` tab; real keys "aisatsu" first composed あいさつ, then letters added, then real Space, Enter):** "挨拶aisatsu" when the IME is switched to half-width alphanumeric **without closing it** and the letters arrive as **real virtual-key events** with no Shift in the key state: `VK_IME_OFF` … `VK_IME_ON`, or `IMC_SETCONVERSIONMODE 0` … saved conv. The composition survives the mode switch. A Space typed in that mode stays in the composition as a half-width space ("挨拶ai satsu"). Fails (composition committed as unconverted kana): posted `WM_CHAR`, `KEYEVENTF_UNICODE`/`VK_PACKET` (even in alphanumeric mode), `IMC_SETOPENSTATUS 0`, and the Microsoft IME's own Shift+letter (gives "あいさつAisatsu", Space then types a space, and leaves the IME in alphanumeric mode). Full-width alphanumeric (conv 8) gives "挨拶ａｉｓａｔｓｕ". With Shift in the key state the letters come out uppercase ("挨拶AISATSU") — the reason the trigger is swallowed.
- **Switching another process's IME — measured in Notepad (2026-10-11, scratch tool `imeswitch.cpp`):** injected `VK_IME_OFF` (→ open=1 conv=0; `VK_IME_ON` → hiragana), `WM_IME_CONTROL/IMC_SETOPENSTATUS 0` (restored by `1`) and `IMC_SETCONVERSIONMODE 0` (restored by the saved conv) all took effect for keys typed right after. `IMC_SETOPENSTATUS 1` on a tab whose IME was off (open=0 conv=25) did **not** make real keys compose, so turning the IME on by IMM message is less reliable than restoring a state saved just before. Not tested: English-layout switch (no en-US layout installed).
- Posted `WM_CHAR` (measured, previous prototype): IME/TSF never see it and Notepad's spell check does not garble it, but it commits a pending composition. `WM_CHAR '\r'` is ignored by Notepad.
- **Verified by the user with real keystrokes (2026-10-11):** the basic flow works ("うまくいきました"; which of the edge cases they tried is not recorded).
- **無変換 / 変換 / カタカナひらがな triggers are unverified with real keys** (only the menu → registry path was checked by posting `WM_COMMAND` to `ime2nd.Main`). Open: the actual vk/scan of these keys on the user's keyboard (HANDOFF says US physical keyboard + Japanese layout). While the IME is ON the key's own function is gone (変換 reconversion, 無変換 / カタカナひらがな mode keys — including a user mapping of 無変換/変換 to "IME off/on").
- **Unverified (prototype):** pressing the trigger while a conversion / candidate list is showing; Excel, Chromium/Electron, Word, VS Code; Google 日本語入力 / ATOK with `VK_IME_ON`/`VK_IME_OFF`; whether a lone Shift tap toggles IME mode on some IME settings (the swallowed trigger never reaches the IME, so likely moot).
- **Known costs of swallowing the trigger while the IME is ON:** Shift+arrow / Shift+Tab / Shift+click and the IME's own Shift+←/→ (clause boundaries) lose the trigger Shift (use the other Shift); a trigger pressed *before* Ctrl/Alt/Win is swallowed, so e.g. Shift then Ctrl+Z gives Ctrl+Z. Restoring via `VK_IME_ON` means hiragana; other modes are corrected 150 ms later.
- **Known limitation, Chromium-based apps (from the popup design; recheck):** an unconfirmed composition stayed pending after the IME was closed. Read in Chromium's `ui/base/ime/win/`: `TSFTextStore::OnEndComposition` is a no-op, nothing reacts to IME open/close, and `ConfirmComposition` only runs on focus change to another input.
