# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Windows 11 tray-resident Win32/C++17 app. While the system IME is ON, Trigger-Shift+a–z, digits, all punctuation keys and Space are swallowed (trigger = left Shift by default; right Shift or CapsLock via the tray menu; with a Shift trigger the other Shift stays a plain Shift) by a low-level keyboard hook and accumulated (each key gives its plain character via `ToUnicodeEx` on the foreground layout — letters lowercase, digits as digits; also holding the other Shift gives the shifted one: A, !, ?, … — Space as a half-width space) in a small popup at the caret; when Shift is released the whole string is injected into the focused app at once. Must run **without admin rights** (`asInvoker`, no `uiAccess`, startup via `HKCU\...\Run` only); elevated apps are intentionally left alone (UIPI). Works on JIS and US layouts (matches virtual keys A–Z, not layout-specific keys). See `README.md` for user-facing behavior.

## Commands

- Build: `build.bat` (or `build.bat debug` → `build-debug\`) → `build\ime2nd.exe`. It finds Visual Studio via `vswhere`, loads `vcvars64.bat`, then runs `cmake --preset release` / `cmake --build --preset release` (Ninja, `CMakePresets.json`). cmake/ninja come from PATH if present, otherwise from the copies bundled with VS (`Common7\IDE\CommonExtensions\Microsoft\CMake`). Installed here: VS 2026 Community (v18). Opening the folder in Visual Studio also works. No test suite or linter.
- New `.cpp` files must be added to `add_executable` in `CMakeLists.txt`; new system libs to its `target_link_libraries` (e.g. `gdi32` was needed for the popup). `src/app.manifest` is listed as a source so CMake embeds it with `mt.exe`; CRT is static (`/MT` via `CMAKE_MSVC_RUNTIME_LIBRARY`).
- In `build.bat`, avoid parenthesized `if (...)` blocks: expanded `Program Files (x86)` paths contain `)` and break them.
- Smoke test: `build\ime2nd.exe --selftest`. It waits 3 s (focus a text field), reports IME state / which caret strategy worked / popup, then runs the real hook for 10 s and reports max callback time. Output goes to `build\selftest.txt` (GUI subsystem, no console).
- Injected input can't be used to test the hook (it ignores `LLKHF_INJECTED`), so the swallow→popup→commit path needs real keystrokes with IME ON.

## Architecture

All of `src/` is wired together in `main.cpp`'s hidden message-only window; modules communicate through `WM_APP_*` messages defined in `common.h`.

Flow: `KeyboardHook` (LL hook, runs on the main thread) decides swallow/pass-through → posts `WM_APP_UPDATE` / `WM_APP_COMMIT` → `WndProc` in `main.cpp` drives `PopupWindow`, `CaretLocator`, and `TextInjector`.

Constraints that shape the code:

- **The hook callback must stay microseconds-fast.** Windows silently removes LL hooks that exceed ~300 ms. So it does no allocation (except once at commit), no SendInput, no UIA; it only flips state and `PostMessage`s. `main.cpp` re-installs the hook every 30 s (`Reinstall`, skipped mid-session) as a guard.
- **Modifier state comes from `GetAsyncKeyState`, not tracked key events.** Missed key-ups (elevated foreground window, injected events) would otherwise leave Shift "stuck" and capture all plain typing. In an LL hook this API returns the state *before* the current event. Only the trigger key counts (`g_settings.triggerVk`: `VK_LSHIFT` by default, `VK_RSHIFT` or `VK_CAPITAL`, chosen in the tray menu and saved as DWORD `TriggerShift` under `HKCUSoftwareime2nd`; `CaptureShiftHeld()`); events of the other Shift never start or end a session (it is only polled with `GetAsyncKeyState` to uppercase a captured letter; with a CapsLock trigger either Shift uppercases), and releasing the trigger ends the session even if the other Shift is still down. **Exception, CapsLock trigger:** its press is swallowed (no Caps Lock toggle) and a swallowed key never reaches the key-state table (measured: `GetAsyncKeyState` stays "up"), so `g_capsHeld` is tracked from events and reset by `KeyboardHook::ResetHeld()` on foreground change, trigger change and the 30 s reinstall tick to recover from a missed key-up. Choosing CapsLock in the menu taps Caps Lock once if it is ON (`TurnOffCapsLockState()` in `main.cpp`; `GetKeyState(VK_CAPITAL) & 1` is the reliable read, the low bit of `GetAsyncKeyState` is always 1), because the swallowed key could never switch it off afterwards; this is not done at startup. On JIS keyboards the unshifted 英数 key is `VK_OEM_ATTN`, not `VK_CAPITAL`, so it is not covered. Swallowed keys are tracked in `g_swallowed[]` so their key-up is also eaten; a repeat/stale key-down is re-evaluated as a fresh press.
- **Commit happens outside the hook:** Shift-up moves the buffer into a heap `std::wstring*` carried in `WM_APP_COMMIT`'s `lParam` (receiver owns/deletes), and `TextInjector` queues it to its own worker thread, which sends it as `SendInput` batches of `KEYEVENTF_UNICODE` events, split after every non-alphanumeric character with a pause (default 150 ms; tray menu "スペース・記号のあとの待ち時間", choices 0/50/100/150/250/400 ms, saved as DWORD `BreakDelayMs` under `HKCUSoftwareime2nd`, read via `g_settings.breakDelayMs`) (Notepad's spell check starts at a space or punctuation and, while it runs, turns pending `VK_PACKET` characters into copies of the last one or drops them: "hoge hoge" → "hoge eeee"; the busy time grows with the document, so the pause is a margin, not a guarantee — see the comment in `TextInjector.cpp`). If the IME is effectively ON the worker first closes it (`ImeState::Suspend`: `IMC_SETOPENSTATUS` 0, polled until it takes effect), then after a short settle delay (30 ms + 3 ms/char, max 250 ms) reopens it and restores the saved conversion mode (`ImeState::Resume`). Without this, TSF apps such as Excel feed the `VK_PACKET` characters into IME composition and the text comes out as garbage full-width letters (technique from Meltype's `EnsureSystemImeClosed`). Every injected event carries `kInjectTag` in `dwExtraInfo`, and the hook ignores all `LLKHF_INJECTED` events so it never sees its own output.
- **IME state** (`ImeState`): cached, refreshed by a worker thread on Shift-down and foreground change (`SetWinEventHook`). Uses `ImmGetDefaultIMEWnd` + `WM_IME_CONTROL/IMC_GETOPENSTATUS` (`ImmGetContext` doesn't work cross-process). **ON means open AND `IME_CMODE_NATIVE` set** (`IMC_GETCONVERSIONMODE`): the Windows 11 Microsoft IME stays "open" in its direct-input (A) mode and only clears the NATIVE bit (ON: open=1, conv=0x9; OFF: open=1, conv=0x0). Windows Terminal / XAML-island windows report open=0 with odd conv values, so they read as OFF. `Current()` falls back to a 30 ms synchronous query only if the cache is >400 ms old; that query uses `SMTO_BLOCK` so the hook can't re-enter. `Unknown` → pass through, unless the tray option "treat unknown as ON" is set.
- **Caret location** (`CaretLocator`) runs on its own MTA thread with fallback order UI Automation TextPattern → MSAA `OBJID_CARET` (Chrome/Google Docs) → `GetGUIThreadInfo.rcCaret` → none. The popup first appears at the mouse position, then `WM_APP_CARET` repositions it; the generation counter (`g_gen`) discards stale results. Password fields are skipped.
- `PopupWindow` is `WS_EX_NOACTIVATE|TOPMOST` and `HTTRANSPARENT` — it must never take focus, or the injected text would go to the wrong window.
- Manifest (`src/app.manifest`) is embedded at link time and sets PerMonitorV2 DPI; all coordinates are physical pixels.

## Gotchas

- **Known limitation, Chromium-based apps (Chrome, Electron such as the Claude desktop app):** if an unconverted/unconfirmed Japanese composition is pending when Shift+letter is captured, it stays pending (still convertible) next to the injected text. Notepad and Excel commit it when the IME is closed; Chromium does not. Read in Chromium's `ui/base/ime/win/`: `TSFTextStore::OnEndComposition` is a no-op, nothing reacts to IME open/close, and `ConfirmComposition` only runs on focus change to another input. Even a manual 半角/全角 key does not commit there, and an injected `VK_IME_OFF` before the IMC close did not help (tried and removed). No safe workaround: injecting Enter would submit chat/search when nothing is composing. Untested idea: Chromium-only clipboard paste (unknown whether paste confirms the composition). The user is waiting for a Chromium-side fix.

- `common.h` defines `WIN32_LEAN_AND_MEAN`; files using `UIAutomation.h` must include `<objbase.h>` first (it defines `interface`). ATL isn't installed — use `Microsoft::WRL::ComPtr`.
- Unverified in a real IME-ON session: whether closing the IME via `IMC_SETOPENSTATUS` makes `VK_PACKET` text bypass composition in Excel (the fix for the garbled-text bug), whether the settle delay before reopening is long enough (too short → the last characters get composed as kana), and whether a lone Shift tap toggles IME mode on some IME settings. Fallback ideas if it fails: send real VK_A–VK_Z keys while the IME is off, or paste via the clipboard.
- Caret-location approach is modeled on Meltype (yksr-melt/Meltype, GPL-3.0); only the technique was used — do not copy its code.
