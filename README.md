# ime2nd

Windows 11 のタスクトレイ常駐アプリ。IME が ON のとき、**未確定の日本語に英字をそのまま混ぜて、まとめて変換**できるようにします。

例: 「aisatsu」と打って未確定の「あいさつ」を作る → 開始キー（初期値は左 Shift）を押しながら `aisatsu` と打つ → 開始キーを離す → Space で変換 → **挨拶aisatsu**

- 開始キーを押している間だけ、IME を「半角英数」に切り替えます（IME は閉じないので、未確定の文字はそのまま残ります）。離すとひらがなに戻ります。
- 開始キーは、IME が ON のときはアプリに渡しません（横取りします）。そのため、押している間に打つ英字は小文字になります。もう一方の Shift も一緒に押すと大文字・Shift 付きの記号になります。
- 横取りするのは、IME が ON だとはっきり判定できたときだけです。IME の状態を取得できないアプリや、正しく報告しないアプリ（Windows Terminal など）では、開始キーは普通のキーとして働きます。
- **パスワード欄では横取りしません。** Chrome・Edge・Electron 製アプリ・WPF などは、パスワード欄でもウィンドウの IME が「ON」のままに見えるので、アクセシビリティ（UI Automation）で「今の欄がパスワード欄か」を調べています。欄を移るたびに確認し、確認が済むまで（ふつう数十 ms）と、確認できなかったアプリでは、開始キーは普通のキーとして働きます。
  - 副作用：UI Automation で問い合わせると、Chromium 系のアプリはアクセシビリティ機能を有効にします。重いページで CPU・メモリの使用量が少し増えることがあります。
- IME が OFF のときは何もしません（開始キーも普通の Shift・無変換などとして働きます）。
- **試作版**です。動作を確認したのはメモ帳だけです（下の「既知の制限」）。

- 管理者権限は不要です（`asInvoker`）。自動起動は `HKCU\...\Run` のみ使用します。
- 管理者として実行すると、エラーを表示して起動しません（管理者権限のアプリへの入力まで見えてしまうため）。
- 管理者権限で動いているアプリ（UIPI）には介入できず、そのアプリでは何もしません。

## ビルド / 実行

```
build.bat            -> build\ime2nd.exe  (CMake + Ninja + MSVC。VS 同梱の cmake を自動で使用)
build\ime2nd.exe     -> 常駐開始（トレイアイコンの右クリックで 有効/無効・開始キー・自動起動・終了）
build\ime2nd.exe --selftest   -> IME状態・変換モード・フック遅延と、20 秒間のフォーカス移動・欄の判定（normal / PASSWORD / unknown）を build\selftest.txt に出力
pwsh -File tools\make-tray-icons.ps1   -> トレイアイコン res\tray-black.ico・res\tray-white.ico を作り直す（-Preview 画像.png で拡大プレビュー）
```

開始キーを押している間も、Backspace・Esc・Enter・矢印などはそのまま IME / アプリに届きます（Backspace で未確定の1文字削除など、IME の普段の動作になります）。開始キー+Space は、未確定の中に半角スペースとして入ります。

## 構成

- `KeyboardHook` — `WH_KEYBOARD_LL`。開始キーだけを扱う（IME ON のときに横取り）。重い処理はしない（約300ms超でフックが外されるため）
- `ImeSwitcher` — 作業スレッド。開始キーを押したら `VK_IME_OFF`、離したら `VK_IME_ON` を注入する
- `ImeState` — `ImmGetDefaultIMEWnd` + `WM_IME_CONTROL(IMC_GETOPENSTATUS / IMC_GETCONVERSIONMODE)`、ワーカースレッドでキャッシュ
- `PasswordFocus` — フォーカスが移るたび（`EVENT_OBJECT_FOCUS` と前面ウィンドウの切り替え）に、ワーカースレッドで UI Automation の `IsPassword` を調べてキャッシュ
- トレイアイコン — キーの形に Shift の矢印と「a」。明るいタスクバーでは黒、暗いタスクバーでは白（`SystemUsesLightTheme` を見て、テーマが変わると切り替え）

## 設定

トレイアイコンの右クリック →「英字入力の開始キー」で、次のうち 1 つを選べます（初期値は左 Shift）。

| 開始キー | `TriggerShift` の値 |
|---|---|
| 左 Shift / 右 Shift | 160 / 161 |
| 無変換 / 変換 | 29 / 28 |
| カタカナひらがな | 242 |

選択は `HKCU\Software\ime2nd` の `TriggerShift` に保存され、次回起動時も有効です（それ以外の値が入っていたときは左 Shift になります）。

どのキーも、**IME が ON の間は横取りする**ので、そのキー本来の働きは IME が ON の間は使えません（IME が OFF なら普通に働きます）。

- **Shift**: もう一方の Shift は通常の Shift として働きます（開始キーを押している間にもう一方も押すと、英字が大文字になります）。
- **無変換 / 変換 / カタカナひらがな**: 押している間にどちらかの Shift も押すと、英字が大文字になります。 IME のキーなので、IME が ON の間は再変換・カタカナ変換などの働きが使えません。IME のキー設定で、これらのキーに「IME オン/オフ」を割り当てている場合、IME をオフにできなくなるので注意してください。カタカナひらがなキーは、Shift などを押したときも同じキーとして扱います（スキャンコードで判定）。

## 既知の制限（試作版）

- IME が ON の間は、開始キーの Shift を Shift+矢印・Shift+Tab・Shift+クリック、変換中の Shift+←/→（文節の区切り直し）に使えません。もう一方の Shift を使ってください。
- Ctrl・Alt・Win を先に押してから開始キーを押したときは、ショートカットとして普通に通します。開始キーを先に押してから Ctrl などを押すと、開始キーの働きは効きません（例: Shift → Ctrl+Z は Ctrl+Z になる）。
- 無変換・変換・カタカナひらがなを開始キーにした場合は、実際のキーで試していません。
- 開始キーを押した直後（数ミリ秒以内）に打った英字は、切り替えが間に合わずひらがなになることがあります。
- 開始キーを離すと、IME はひらがなモードに戻ります。元がカタカナなど別のモードだったときは、少し遅れて元のモードに戻します。
- Microsoft IME で確認しました。Google 日本語入力・ATOK、および Excel・Chrome などのアプリでの動作は未確認です。
